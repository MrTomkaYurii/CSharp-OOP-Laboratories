# Лабораторна робота №12: Комунікація між об'єктами та події в C# (.NET 10)

## 🎯 Мета роботи
Практичне засвоєння механізмів міжоб'єктної взаємодії, делегатів, подій (**Events**) та поведінкових патернів проектування:
- Застосування стандартного шаблону подій .NET (`event EventHandler<TEventArgs>`);
- Реалізація патерну Спостерігач (Observer Pattern) через механізм підписки та відписки від подій (`+=`, `-=`);
- Реалізація життєвого циклу завдань за допомогою подій завершення роботи;
- Дотримання принципу інверсії залежностей (DIP) та патерну Стратегія (Strategy Pattern) при проектуванні модульних калькуляторів.

## 📋 Перелік практичних завдань

| Проект | Назва завдання | Архітектура та опис завдання |
| :---: | :--- | :--- |
| **01** | **Реалізація події (Event Implementation)** | Канонічна реалізація події у .NET: клас `Dispatcher` генерує подію `NameChange` з кастомним `NameChangeEventArgs`, а клас `Handler` підписується на неї методом `OnNameChange`. |
| **02** | **Королівський гамбіт (King’s Gambit)** | Патерн Спостерігач на подіях C#: Король генерує подію атаки `UnderAttack`. Королівська варта (`RoyalGuard`) та піхотинці (`Footman`) підписані на подію. При загибелі воїн відписується від події короля. |
| **03** | **Інверсія залежностей (Dependency Inversion)** | Гнучкий калькулятор `Calculator`, робота якого залежить від абстракції `ICalculationStrategy`. Динамічне перемикання стратегій додавання, віднімання, множення та ділення під час виконання. |
| **04** | **Робоча сила (Work Force)** | Подійно-орієнтована черга виконання завдань: об'єкти `Job` виконуються співробітниками (`StandardEmployee`, `PartTimeEmployee`). При досягненні 0 залишку годин робота генерує подію завершення `JobDone` і видаляється зі списку. |
| **05** | **Розширений королівський гамбіт (King’s Gambit Extended)** | Розширення задачі 02: додавання очок здоров'я захисникам (піхотинець витримує 2 удари, гвардієць — 3 удари). Лише після вичерпання здоров'я воїн гине та відписується від подій короля. |
